# Внедрение Jana Hub в компании

Документ описывает, как перенести Jana Hub из демо в рабочую среду Jana Post:
- подключить существующую базу сотрудников;
- связать платформу с 1С:ЗУП, Documentolog и почтой;
- развернуть систему в контуре компании;
- запустить её для людей поэтапно.

Всё, что помечено **«готово»**, уже работает в репозитории. Пометка **«план»** означает следующий шаг разработки.

---

## 1. Что внедряем и откуда берутся данные

| Модуль Jana Hub | Источник данных | Направление | Статус |
|---|---|---|---|
| Профиль сотрудника, оргструктура, руководители | 1С:ЗУП или файл Excel/CSV | 1С → Jana Hub | **готово**: импорт файла и синхронизация с 1С |
| Остаток отпуска | 1С:ЗУП | 1С → Jana Hub | **готово**: поле в импорте и синхронизации |
| Заявки «Отпуск» и «Аванс» | Jana Hub | Jana Hub → 1С:ЗУП, Documentolog | mock-адаптеры готовы, боевые — **план** (раздел 5) |
| Учётные записи и вход | Jana Hub (пароль по ссылке-приглашению) | — | **готово**; SSO через AD — **план** |
| Jana Academy, награды, AI Jana | Jana Hub | — | **готово** |
| Уведомления и приглашения | SMTP (Gmail, Exchange, Postfix) | Jana Hub → почта | **готово** |

Главный принцип: **1С:ЗУП остаётся единственным источником кадровых данных.** Jana Hub не редактирует ФИО, должности и даты приёма. Он получает их из 1С и показывает сотруднику, а возвращает в 1С только заявления.

---

## 2. Архитектура в контуре компании

```
 Сотрудники (браузер, телефон)
        │ HTTPS
        ▼
 ┌──────────────── Сервер Jana Hub (ЦОД в РК) ────────────────┐
 │  nginx (TLS) ── frontend (React)                           │
 │      └──────── backend (FastAPI) ── PostgreSQL             │
 │                      │        └── Ollama (локальная LLM)   │
 └──────────────────────┼─────────────────────────────────────┘
                        │ внутренняя сеть / VPN
        ┌───────────────┼──────────────────┬─────────────────┐
        ▼               ▼                  ▼                 ▼
   1С:ЗУП           Documentolog      Почтовый сервер    Active Directory
 (HTTP-сервис       (регистрация      (SMTP:             (SSO для офиса,
  или OData)         заявлений)        приглашения)       план)
```

- Сервер с персональными данными размещается **в Казахстане** (см. раздел 7).
- 1С:ЗУП не выставляется в интернет. Backend Jana Hub обращается к ней по внутренней сети или VPN под отдельной учётной записью только на чтение.
- Языковая модель работает на собственном сервере (Ollama), поэтому вопросы сотрудников и кадровые данные не уходят во внешние AI-сервисы.

## 3. Подключение существующей базы сотрудников

Есть четыре способа. Их можно сочетать: например, первая загрузка из Excel, а дальше ежедневная синхронизация с 1С.

| Способ | Что нужно от компании | Скорость запуска | Актуальность данных | Статус |
|---|---|---|---|---|
| **A. Файл Excel/CSV** из 1С или таблицы HR | выгрузка списка сотрудников | 1 день | вручную, по мере загрузки | **готово** |
| **B. HTTP-сервис 1С:ЗУП** (рекомендуемый) | небольшое расширение 1С (≈1–2 дня программиста 1С) | 1–2 недели | автоматически, каждую ночь или каждый час | **готово** со стороны Jana Hub |
| **C. Стандартный OData 1С** | публикация базы на веб-сервере и включение OData | 1 неделя | автоматически | **готово**, нужна настройка соответствия полей |
| **D. Файл по расписанию** | 1С каждую ночь кладёт выгрузку в общую папку | 2–3 дня | раз в сутки | **готово** (команда CLI + cron) |

### 3.1. Как устроена загрузка (общее для всех способов)

Ключ сотрудника — **табельный номер** (код сотрудника в 1С). Повторная загрузка того же файла ничего не ломает: изменится только то, что действительно поменялось.

Перед применением HR видит **предпросмотр**:
- **новые сотрудники** создаются вместе с учётной записью (если есть email) и отправкой ссылки-приглашения;
- **изменения** — новая должность, перевод в другой отдел, смена руководителя, обновлённый остаток отпуска; каждое показывается как «было → стало»;
- **увольнения** (заполнена «Дата увольнения») — доступ в Jana Hub блокируется, ссылки-приглашения отзываются;
- **ошибки** с номером строки: нет обязательного поля, неверная дата или email, руководитель не найден, дубль табельного номера или email. Строки с ошибками пропускаются, остальные загружаются;
- **полная сверка** (по галочке) — список тех, кто есть в Jana Hub, но пропал из источника. Им можно заблокировать доступ.

Правила:
- руководитель определяется по колонке «Табельный номер руководителя» или по ФИО в колонке «Руководитель»;
- роль «Руководитель» назначается автоматически всем, у кого есть подчинённые, или берётся из колонки «Роль». **Роль HR через импорт выдать нельзя**, только вручную;
- новичкам, принятым за последние 60 дней, автоматически назначается траектория «Адаптация новичка».

Каждая загрузка сохраняется в истории: кто загрузил, когда, сколько создано и изменено.

### 3.2. Способ A — файл Excel/CSV (готово)

1. HR-панель → **Импорт сотрудников** → «Шаблон» (или своя выгрузка из 1С: отчёт «Список сотрудников» → «Сохранить как» .xlsx).
2. Колонки распознаются по названию, порядок не важен:

| Колонка | Обязательна | Пример |
|---|---|---|
| Табельный номер (или «Таб. №», «Код») | да | ZUP-1002 |
| ФИО (или «Сотрудник») | да | Иванова Ольга Петровна |
| Должность | да | Кладовщик |
| Подразделение (или «Отдел») | да | Склад Алматы |
| Дата приёма | да | 15.06.2023 |
| Email | для доступа | olga.i@company.kz |
| Телефон | нет | +7 701 000 00 11 |
| Табельный номер руководителя (или «Руководитель» с ФИО) | нет | ZUP-1001 |
| Остаток отпуска | нет | 18 |
| Роль | нет | сотрудник / руководитель |
| Дата увольнения | нет | 01.10.2026 |

3. Перетащите файл (.xlsx или .csv, UTF-8 или Windows-1251) → проверьте предпросмотр → «Применить».

То же из командной строки на сервере:

```bash
docker compose exec backend python -m app.cli import-employees /data/employees.xlsx            # предпросмотр
docker compose exec backend python -m app.cli import-employees /data/employees.xlsx --apply --invite
```

### 3.3. Способ B — HTTP-сервис 1С:ЗУП (рекомендуемый)

В 1С:ЗУП добавляется **расширение** с одним HTTP-сервисом. Расширение не меняет типовую конфигурацию, поэтому обновления 1С не ломаются. Сервис отдаёт список сотрудников сразу в формате Jana Hub:

`GET https://1c.company.kz/zup/hs/janahub/employees`

```json
{
  "employees": [
    {
      "external_id": "ZUP-1002",
      "full_name": "Иванова Ольга Петровна",
      "email": "olga.i@company.kz",
      "phone": "+7 701 000 00 11",
      "position": "Кладовщик",
      "department": "Склад Алматы",
      "manager_external_id": "ZUP-1001",
      "hire_date": "2023-06-15",
      "vacation_balance_days": 18,
      "dismissal_date": null
    }
  ]
}
```

Набросок модуля HTTP-сервиса для программиста 1С. Имена регистров и реквизитов нужно сверить с конкретной редакцией ЗУП:

```bsl
Функция EmployeesGET(Запрос)
    Запрос1С = Новый Запрос;
    Запрос1С.Текст =
    "ВЫБРАТЬ
    |    Сотр.Код КАК external_id,
    |    Сотр.Наименование КАК full_name,
    |    Тек.ТекущаяДолжность.Наименование КАК position,
    |    Тек.ТекущееПодразделение.Наименование КАК department,
    |    Тек.ДатаПриема КАК hire_date,
    |    Тек.ДатаУвольнения КАК dismissal_date
    |ИЗ
    |    Справочник.Сотрудники КАК Сотр
    |    ЛЕВОЕ СОЕДИНЕНИЕ РегистрСведений.ТекущиеКадровыеДанныеСотрудников КАК Тек
    |    ПО Тек.Сотрудник = Сотр.Ссылка
    |ГДЕ НЕ Сотр.ПометкаУдаления";
    // Дополнить: email из контактной информации физлица,
    // руководителя подразделения, остаток отпуска на текущую дату.
    Ответ = Новый HTTPСервисОтвет(200);
    Ответ.Заголовки.Вставить("Content-Type", "application/json; charset=utf-8");
    Ответ.УстановитьТелоИзСтроки(СериализоватьВJSON(Запрос1С.Выполнить().Выгрузить()));
    Возврат Ответ;
КонецФункции
```

Настройка Jana Hub (`.env` на сервере):

```dotenv
ZUP_URL=https://1c.company.kz/zup/hs/janahub/employees
ZUP_USER=janamen_reader          # пользователь 1С только с правом чтения
ZUP_PASSWORD=********
```

После перезапуска в HR-панели на карточке «Синхронизация с 1С:ЗУП» появится статус «Подключено» с числом сотрудников. Кнопка «Получить данные из 1С» строит тот же предпросмотр, что и для файла.

### 3.4. Способ C — стандартный OData 1С (без доработки конфигурации)

1. В конфигураторе: «Администрирование» → «Публикация на веб-сервере», отметить «Публиковать стандартный интерфейс OData».
2. В режиме предприятия: «Администрирование» → «Синхронизация данных» → «Настройки стандартного интерфейса OData». Создать отдельного пользователя, на вкладке «Состав» включить нужные справочники и регистры.
3. Указать адрес объекта и соответствие полей:

```dotenv
ZUP_URL=https://1c.company.kz/zup/odata/standard.odata/Catalog_Сотрудники?$format=json&$expand=...
ZUP_FIELD_MAP={"external_id":"Code","full_name":"Description","position":"Должность.Description","department":"Подразделение.Description","hire_date":"ДатаПриема"}
```

`ZUP_FIELD_MAP` сопоставляет поля Jana Hub с полями ответа 1С. Вложенные поля пишутся через точку.

Минусы OData: кадровые данные в ЗУП разнесены по нескольким регистрам, большие выборки работают медленно, а схема зависит от версии конфигурации. Поэтому для боевой работы мы рекомендуем способ B.

### 3.5. Способ D — файл по расписанию

Если прямой доступ к 1С закрыт политикой ИБ, 1С может каждую ночь выгружать файл в общую папку, смонтированную в контейнер. Регламентное задание 1С или ручная выгрузка HR забирается командой по cron:

```cron
# каждый день в 06:30
30 6 * * *  cd /opt/janamen && docker compose exec -T backend python -m app.cli import-employees /data/zup/employees.xlsx --apply --invite >> /var/log/janamen-import.log 2>&1
```

### 3.6. Автоматическая синхронизация

Для способов B и C:

```cron
# каждую ночь: новые сотрудники получают приглашение, уволенные теряют доступ
0 3 * * *  cd /opt/janamen && docker compose exec -T backend python -m app.cli sync-zup --apply --invite >> /var/log/janamen-sync.log 2>&1
```

Без `--apply` команда только показывает отчёт. Это удобно для первой проверки. Флаг `--block-missing` блокирует тех, кого больше нет в 1С; его стоит включать после того, как первая загрузка проверена.

### 3.7. Порядок первой загрузки (чек-лист)

1. Выгрузить из 1С полный список работающих сотрудников с табельными номерами руководителей.
2. Загрузить файл на **тестовом стенде**, исправить ошибки в источнике и повторить загрузку, пока ошибок не останется.
3. На боевом сервере применить загрузку **без приглашений** (снять галочку), чтобы проверить оргструктуру в разделе «Команда» у нескольких руководителей.
4. Отправить приглашения **волнами**:
   - сначала HR и руководители;
   - затем пилотный отдел;
   - затем остальные (повторная загрузка с галочкой, или во вкладке «Доступы»).
5. Включить ночную синхронизацию (3.6).

## 4. Как сотрудники получают доступ

| Категория | Способ входа | Статус |
|---|---|---|
| Офис с корпоративной почтой | ссылка-приглашение на почту, пароль сотрудник задаёт сам | **готово** |
| Склад, водители, курьеры без корпоративной почты | личная почта из 1С (с согласия сотрудника); руководитель выдаёт ссылку вручную во вкладке «Доступы» | **готово** |
| Те же категории, следующий шаг | вход по номеру телефона с SMS-кодом; QR-код приглашения на смене; общий планшет-киоск на складе | **план** |
| Офис, следующий шаг | единый вход через Active Directory / Keycloak (OIDC), без отдельного пароля | **план** |

Безопасность приглашений:
- ссылка одноразовая и действует 72 часа;
- в базе хранится только SHA-256 токена;
- новая ссылка отменяет предыдущие;
- увольнение или блокировка сразу обрывает доступ.

Для боевой среды задайте `EXPOSE_INVITE_LINKS=false`: тогда HR не видит саму ссылку, она уходит только на почту.

## 5. Обратная интеграция: заявки → 1С:ЗУП и Documentolog

Сейчас при оформлении заявки HR вызываются mock-адаптеры (`backend/app/integrations/mock_1c_zup.py`, `mock_documentolog.py`). Чтобы подключить боевые системы, нужно написать класс с тем же интерфейсом (`HRSystemAdapter`, `DocumentFlowAdapter` в `integrations/base.py`) и переключить переменную `HR_SYSTEM_PROVIDER` или `DOCFLOW_PROVIDER`. Остальной код не меняется.

| Действие в Jana Hub | Что происходит в 1С:ЗУП | Как |
|---|---|---|
| HR оформил отпуск | создаётся документ «Отпуск» по сотруднику с датами | POST в HTTP-сервис расширения (тот же, что в 3.3) |
| HR оформил аванс | создаётся документ начисления или выплаты аванса | POST в HTTP-сервис |
| Запрос остатка отпуска | актуальный остаток на дату | GET в HTTP-сервис, кэш на сутки |

Documentolog: заявление регистрируется как входящий документ с приложенным PDF заявки. Подписание ЭЦП сотрудника и руководителя идёт через NCALayer. Это **план**: способ интеграции (API или модуль) нужно согласовать с Documentolog. В их опубликованных материалах упоминается готовый модуль интеграции с 1С и планы автоматизировать кадровые приказы с 1С:ЗУП.

## 6. Инфраструктура

| Компонент | Минимум для 300–1000 сотрудников |
|---|---|
| Приложение (nginx, frontend, backend, PostgreSQL) | 4 vCPU, 8 ГБ RAM, 100 ГБ SSD |
| Локальная LLM (Ollama, модель `qwen2.5:3b`) | +4 vCPU, +8 ГБ RAM. С GPU 8+ ГБ можно взять `qwen2.5:7b` для более качественных ответов |
| ОС | Ubuntu 22.04/24.04 LTS, Docker и Docker Compose |

Что сделать перед запуском в прод:

1. **Отключить демо-режим:**
   ```dotenv
   SEED_ON_STARTUP=false
   RESET_DB_ON_SCHEMA_CHANGE=false
   JWT_SECRET=<длинная случайная строка>
   POSTGRES_PASSWORD=<сложный пароль>
   EXPOSE_INVITE_LINKS=false
   APP_BASE_URL=https://janamen.jana.kz
   ```
   В демо база пересоздаётся при изменении схемы. В проде это недопустимо, поэтому дальше схема обновляется миграциями (Alembic — **план**).
2. **HTTPS:** nginx или корпоративный балансировщик с сертификатом. Доступ из интернета только к 443, API и база закрыты.
3. **Почта:** корпоративный SMTP (Exchange или Postfix) вместо Gmail, отправитель вида `janamen@jana.kz`, настроенные SPF и DKIM.
4. **Резервные копии:** `pg_dump` каждую ночь с хранением 30 дней на отдельном хранилище в РК, раз в месяц — проверочное восстановление.
5. **Мониторинг:**
   - `/api/integrations` показывает статус 1С, почты и LLM;
   - логи контейнеров собираются в корпоративный стек (ELK, Loki);
   - алерт, если ночная синхронизация завершилась с ошибкой.
6. **Обновления:** `git pull && docker compose up -d --build` в окно обслуживания.

## 7. Безопасность и требования законодательства РК

> Ниже — ориентиры для команды. Перед запуском их нужно проверить с юристом компании по актуальной редакции закона на adilet.zan.kz.

- **Хранение данных в Казахстане.** Закон РК № 94-V «О персональных данных и их защите» (п. 2 ст. 12) требует хранить персональные данные в базе, расположенной на территории РК. Сервер Jana Hub, резервные копии и сервер LLM размещаются в ЦОД или серверной компании в Казахстане.
- **Согласие сотрудника** на обработку персональных данных (ст. 8). Его стоит включить в шаг активации учётной записи (галочка со ссылкой на положение), это **план**. Объём данных минимален: Jana Hub не хранит ИИН, адреса и оклады.
- **Автоматизированные решения.** AI Jana и аналитика только подсказывают: решения по отпускам, авансам и наградам принимает человек (руководитель или HR), и это видно в истории заявки. Это важно, поскольку закон отдельно регулирует обработку, которая порождает правовые последствия без участия человека.
- **Разграничение доступа** проверяется на бэкенде:
  - сотрудник видит только себя;
  - руководитель — только своих подчинённых;
  - HR — всех.
- **Журнал доступа:** каждый просмотр досье и выгрузка отчёта записываются. HR видит журнал командой `/журнал` в AI Jana.
- **Интеграции:** отдельные технические пользователи 1С с минимальными правами, пароли только в `.env` на сервере (или в Vault), не в репозитории.
- **Геймификация:** рейтинги и благодарности не используются для кадровых решений и премирования без согласования с HR. Кадровые события (отпуск, больничный, аванс) очков не дают.

## 8. План внедрения по этапам

| Этап | Срок | Что делаем | Результат |
|---|---|---|---|
| **0. Подготовка** | 2 недели | сервер в РК, HTTPS, SMTP; выгрузка сотрудников; расширение 1С (способ B); положение о персональных данных; каталог наград и бюджет | тестовый стенд с реальной оргструктурой |
| **1. Пилот** | 4–6 недель | один отдел (например, «Логистика», 30–80 человек): заявки онлайн, Academy, AI Jana, награды | метрики пилота и список доработок |
| **2. Тиражирование** | 1–3 месяца | волнами по филиалам и складам; ночная синхронизация с 1С; обучение руководителей | 80%+ сотрудников активировали доступ |
| **3. Развитие** | далее | боевые адаптеры 1С и Documentolog, SSO, SMS-вход, мобильное приложение (PWA), больничные и справки | полностью безбумажные кадровые процессы |

## 9. Как вовлечь сотрудников

- **Запуск через руководителя.** На планёрке руководитель показывает, как подать отпуск за 2 минуты, и сам ставит команде цель отдела в «Наградах».
- **Первая неделя.** Траектория «Адаптация новичка» засчитывается всем в пилоте, за её прохождение — бонус XP. Первые награды магазина (кружка, худи) достаются быстро и видны коллегам.
- **QR-плакаты на складах** со ссылкой на вход и короткой инструкцией на русском и казахском.
- **Благодарности** коллегам в первую неделю делает сам руководитель, чтобы показать пример.
- **Обратная связь:** вопросы, на которые AI Jana не ответила, уходят в HR. Раз в неделю HR дополняет базу знаний этими вопросами (папка `backend/knowledge_base/`).

## 11. Риски и что с ними делать

| Риск | Мера |
|---|---|
| Ошибки в данных 1С (нет руководителей, дубли email) | предпросмотр с ошибками по строкам, исправление в 1С, а не в Jana Hub |
| У складских сотрудников нет почты | личная почта с согласия, выдача ссылки руководителем, SMS-вход (план) |
| Сопротивление «ещё одной системе» | запуск через руководителей, заявки только онлайн после пилота, ощутимые награды |
| Нагрузка на HR при запуске | загрузка волнами, автоматические приглашения, AI Jana отвечает на типовые вопросы |
| Изменение структуры 1С при обновлении | интеграция через расширение (способ B), а не через типовые объекты |
| Утечка персональных данных | хранение в РК, HTTPS, роли, журнал доступа, отдельные технические пользователи, бэкапы |

## 12. Чек-лист запуска

- [ ] Сервер в РК, HTTPS, домен, SMTP с SPF и DKIM
- [ ] `.env` боевой: `SEED_ON_STARTUP=false`, `RESET_DB_ON_SCHEMA_CHANGE=false`, новый `JWT_SECRET`, `EXPOSE_INVITE_LINKS=false`
- [ ] Положение о персональных данных и согласие сотрудника
- [ ] Расширение 1С (HTTP-сервис) или регламентная выгрузка файла
- [ ] Первая загрузка проверена на тестовом стенде, ошибок 0
- [ ] Учётные записи HR созданы вручную
- [ ] Каталог наград и бюджет согласованы
- [ ] Ночная синхронизация и бэкапы в cron, алерты настроены
- [ ] Руководители пилота обучены, приглашения отправлены
