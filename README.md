# JanaMen — единая HR-платформа сотрудника

Jana Post × Terricon Valley Hackathon 2026 · **Challenge 02 / Digital HR**

Один вход, а в нём профиль, HR-заявки, обучение (Jana Academy), AI-ассистент (AI Jana) и уведомления.

## Быстрый старт без Docker (macOS)

Нужны Python 3.10–3.13 и Node.js 18+ (`brew install python@3.13 node`).

```bash
./start.sh
```

Скрипт сам поставит зависимости и поднимет бэкенд (:8000, SQLite) и фронт: http://localhost:5173. AI Jana в этом режиме отвечает цитатами из базы знаний. Остановить — Ctrl+C.

## Быстрый старт (Docker)

Нужен Docker Desktop. Для локальной модели выделите ему **не меньше 6 ГБ RAM**: Settings → Resources.

```bash
cp .env.example .env
docker compose up --build        # или: make up
```

- Веб: http://localhost:3000
- API и Swagger: http://localhost:8000/docs
- Статус интеграций и LLM: http://localhost:8000/api/integrations

Что поднимается: `db` (PostgreSQL), `backend` (FastAPI), `frontend` (nginx), `ollama` (локальная LLM) и `ollama-init`. Последний один раз скачивает модель `qwen2.5:3b` (~2 ГБ) и завершается. Пока модель качается, AI Jana отвечает цитатами из базы знаний. Ход скачивания: `docker compose logs -f ollama-init`.

### Режим разработки (hot reload)

```bash
docker compose -f docker-compose.yml -f docker-compose.dev.yml up --build   # или: make dev
```

Фронт откроется на http://localhost:5173. Код `backend/` и `frontend/` смонтирован в контейнеры, поэтому изменения подхватываются без пересборки.

### Локальная LLM: два режима

| Режим | Как включить | Когда использовать |
|---|---|---|
| **Ollama в Docker** (по умолчанию) | `COMPOSE_PROFILES=ai` в `.env` | Всё одной командой, одинаково у всех |
| **Ollama на хосте** | `brew install ollama`, `ollama serve`, `ollama pull qwen2.5:3b`; в `.env`: `COMPOSE_PROFILES=` и `OLLAMA_BASE_URL=http://host.docker.internal:11434` | На Mac в 3–5 раз быстрее: Docker на macOS не видит GPU Apple Silicon |
| Без LLM | `LLM_PROVIDER=none` | Только цитаты из базы знаний, ничего скачивать не нужно |

Модель меняется переменной `LLM_MODEL`. Например, `qwen2.5:7b` даёт ответы лучше, но работает медленнее.

### Локально без Docker

```bash
# backend (SQLite, тестовые данные создаются автоматически)
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload            # http://localhost:8000

# frontend (в другом терминале)
cd frontend
npm install
npm run dev                               # http://localhost:5173, /api проксируется на :8000
```

Сбросить демо-данные: удалить `backend/janamen.db` (или `docker compose down -v`) и перезапустить.

### Тесты

```bash
cd backend && pytest -q
```

## Jana Academy: траектории и геймификация

**Траектории.** Это наборы курсов, которые проходятся по порядку. Следующий обязательный курс открывается, когда пройден предыдущий.

| Траектория | Для кого | Курсы |
|---|---|---|
| Адаптация новичка | все новые сотрудники, назначается автоматически при трудоустройстве | Добро пожаловать в Jana Post, HR-заявки в JanaMen, Информационная безопасность |
| Логистика и склад | склад, сортировка, доставка | Охрана труда, Трансграничная доставка, Сервис для клиента (по желанию) |
| Руководитель | руководители | Обратная связь, Согласование заявок, Информационная безопасность (по желанию) |

Сотрудник может начать траекторию сам. Руководитель или HR назначает её на странице «Команда» (кнопка «Обучение»): курсы добавляются со сроком, сотрудник получает уведомление. За 3 дня до срока приходит напоминание.

**Опыт (XP).** Начисляется один раз за каждое действие, накрутить повторами нельзя.

| Действие | XP |
|---|---|
| урок | +10 |
| курс пройден | +50 |
| тест на 100% | +25 |
| тест с первой попытки | +15 |
| курс пройден раньше срока | +20 |
| серия дней | +5 за каждый день подряд, до +35 |
| траектория завершена | +150…200 |

**Уровни:** Стажёр → Курьер (100) → Экспедитор (250) → Логист (500) → Мастер маршрута (900) → Легенда Jana Post (1500).

**Бейджи (10):**
- «Первый шаг»;
- «Первая посылка»;
- «Точно в цель»;
- «С первой попытки»;
- «Раньше срока»;
- «Разгон» (3 дня подряд);
- «Неделя без пропусков»;
- «Маршрут пройден»;
- «Книжный червь» (5 курсов);
- «Логист».

**Рейтинг.** По отделу или по всей компании, за неделю или за всё время. Подсказывает, сколько XP осталось до соседа выше.

После урока или теста всплывает карточка с начисленным XP. Новый бейдж, уровень или завершённая траектория показываются праздничным окном с конфетти.

Демо: Нурланова Алия занимается 3 дня подряд и отстаёт от Ахметова в недельном рейтинге на 5 XP. Чтобы обогнать его, достаточно одного урока. Если пройти «Информационную безопасность», завершится траектория «Адаптация новичка» и откроется уровень «Логист».

## Мотивация: награды, благодарности, цели отдела

Раздел **«Награды»** в меню.

1. **Jana-коины и магазин наград.** Каждый полученный XP превращается в коин (1 XP = 1 коин). HR ведёт каталог: цена, остаток, иконка, показ в магазине. В демо 7 наград:
   - кружка Jana Post;
   - парковочное место на месяц;
   - обед с руководителем;
   - худи Jana Post;
   - приоритет в выборе дат отпуска;
   - выходной в день рождения;
   - внешний курс за счёт компании.

   При обмене коины сразу списываются, и заявка уходит в HR (HR-панель → «Награды и цели»). Если HR отклонит заявку или сотрудник сам её отменит, коины возвращаются.
2. **Посылка благодарности.** Сотрудник благодарит коллегу за одну из ценностей компании: Открытость, Надёжность или Результат.
   - Получатель получает +15 XP, отправитель +5 XP.
   - Не больше 3 благодарностей в неделю, себя поблагодарить нельзя.
   - Все благодарности видны в общей ленте (фильтры «Все», «Мой отдел», «Мне»).
   - Бейджи «Спасибо!» и «Душа команды».
3. **Цель отдела.** Руководитель (на странице «Команда») или HR ставит отделу общую цель по XP со сроком и наградой, например «900 XP до конца месяца → пицца-пятница».
   - Прогресс показан фургоном, который едет к финишу.
   - Видно, кто внёс больше всех и каков вклад каждого.
   - Когда цель достигнута, все сотрудники отдела получают уведомление.
4. **Честная серия.** Выходные и дни одобренного отпуска не прерывают серию дней. Раз в неделю срабатывает автоматическая «заморозка»: один пропущенный рабочий день не сбрасывает серию.

Кадровые события (отпуск, аванс, больничный) очков не дают: геймификация касается только обучения и признания коллег.

## AI Jana для руководителя и HR

В чате AI Jana руководитель и HR могут вызвать аналитику по сотрудникам. Для этого достаточно набрать `/` (появится подсказка) или написать вопрос обычным текстом, например «кто давно не был в отпуске?» или «покажи Ахметова».

| Команда | Кому | Что показывает |
|---|---|---|
| `/команда` | руководитель, HR | Сводка по каждому сотруднику: стаж, остаток отпуска, дни без отпуска, авансы, курсы, главный сигнал. Выгрузка в CSV для Excel |
| `/сотрудник Фамилия` | руководитель, HR | Досье: вся история с даты приёма по сегодня, отпуска и авансы по годам, курсы, сигналы |
| `/отпуска` | руководитель, HR | График на 90 дней, пересечения отпусков, кто давно не отдыхал, накопленные остатки |
| `/авансы` | руководитель, HR | Авансы за 12 месяцев: по месяцам, по людям, частые авансы |
| `/обучение` | руководитель, HR | Прогресс, баллы и просроченные курсы |
| `/ждут` | руководитель, HR | Заявки, ожидающие решения, с подсказками: пересечения, остаток после отпуска, предыдущие авансы |
| `/риски` | руководитель, HR | Все сигналы с рекомендациями, начиная с важных |
| `/отделы` | HR | Сравнение отделов |
| `/найм` | HR | Кандидаты, новички до 90 дней, неактивированные доступы |
| `/журнал` | HR | Журнал доступа: кто и когда смотрел данные сотрудников |
| `/я` | все | Личная статистика сотрудника |

Как устроено:
- Все цифры считает код (`backend/app/services/analytics.py`) по данным 1С:ЗУП, заявок и Jana Academy, а не языковая модель. Если Ollama включена, модель только формулирует 2–3 рекомендации по уже посчитанным фактам. Ответ, в котором есть число, отсутствующее в фактах, отбрасывается.
- Права доступа проверяются на бэкенде: руководитель видит только своих прямых подчинённых, HR — всю компанию, сотрудник — только себя. На запрос о сотруднике из другого отдела приходит отказ, и он тоже попадает в журнал.
- Каждый просмотр досье и сводок, а также каждая выгрузка CSV записываются в журнал доступа (`audit_log`).
- Сигналы:
  - больше 9 и 12 месяцев без отпуска;
  - остаток от 28 дней;
  - 3 и более аванса за полгода;
  - просроченный курс;
  - заявка ждёт решения 3 и более дней;
  - новичок без пройденного вводного курса;
  - учётная запись не активирована.
- В демо-данных есть история с 2020 года. Например, Сейткали Нурбол: 41 день в остатке, 14 месяцев без отпуска, его отпуск пересекается с отпуском Нурлановой.

## Доступ сотрудников: как это работает

Сотрудники не регистрируются сами. Доступ выдаёт HR в разделе **HR-панель**.

1. **Кандидаты.** HR заносит человека ещё до собеседования: ФИО, контакты, должность, подразделение, будущий руководитель, дата собеседования, заметки. Статусы кандидата:
   - «Ожидает собеседования»;
   - «Прошёл собеседование»;
   - «Не прошёл собеседование»;
   - «Трудоустроен»;
   - «Откреплён» (убран из работы, его можно вернуть).
2. **Трудоустройство** доступно только после успешного собеседования. При нём создаётся запись в 1С:ЗУП (mock) и учётная запись JanaMen со статусом «Ожидает активации». Новичку автоматически назначается вводный курс, а руководитель получает уведомление.
3. **Ссылка-приглашение** уходит на email сотрудника (в демо письмо не отправляется, ссылка показывается HR для копирования). По ссылке сотрудник сам придумывает пароль и сразу попадает в кабинет.
4. **Доступы.** Во вкладке «Доступы» HR может:
   - отправить ссылку заново;
   - сбросить пароль (тем же механизмом);
   - заблокировать или разблокировать сотрудника.

Как обеспечена безопасность:
- ссылка одноразовая и действует 72 часа, новая отменяет предыдущие;
- в базе хранится только SHA-256 токена;
- пароль знает только сотрудник: не короче 8 символов, обязательно буквы и цифры;
- с ролью HR работают только HR-эндпоинты (`/api/hr/*`), остальные роли получают 403;
- роль HR при трудоустройстве выдать нельзя;
- блокировка сразу обрывает сессию и отменяет ссылки.

### Отправка писем через Gmail

1. В аккаунте Google, с которого пойдут письма, включите двухэтапную аутентификацию.
2. Создайте пароль приложения: https://myaccount.google.com/apppasswords (16 символов).
3. Пропишите в `.env`:
   ```
   SMTP_USER=ваш.адрес@gmail.com
   SMTP_PASSWORD=xxxx xxxx xxxx xxxx
   ```
4. Перезапустите: `make dev`. При `MAIL_PROVIDER=auto` (по умолчанию) почта включится сама. Проверить режим можно на http://localhost:8000/api/integrations (блок `mail`).

Если отправка не удалась (неверный пароль, нет сети), трудоустройство всё равно проходит, а HR видит причину ошибки и ссылку, чтобы передать её вручную. Для демо заведите кандидата со своим реальным email. Чтобы открыть ссылку из письма на телефоне, укажите в `.env` `DEV_APP_BASE_URL=http://<IP вашего Mac>:5173`. Без Docker те же переменные кладутся в `backend/.env`.

> После обновления со старой версии нужно пересоздать демо-базу: `make reset` (Docker) или удалить `backend/janamen.db`.
